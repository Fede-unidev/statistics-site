What the default experiment shows


The curve y² = x³ + 7 (mod 17) has 18 points (17 affine points plus the point at infinity). The base point G = (1, 5) does not generate the whole group: its order is n = 9, so 9G = ∞ and the sequence kG repeats with period 9. The multiples are (1,5), (2,10), (5,9), (12,1), (12,16), (5,8), (2,7), (1,12): only 8 distinct "public keys" exist, whatever the private key. The "Orders" button confirms the group structure: 1 point of order 2, 2 of order 3, 2 of order 6, 6 of order 9 and 6 of order 18, so the group is cyclic of order 18 and a point of order 18 would generate everything. A small order means the key space is tiny: Q = kG can be inverted by simply trying every k up to n. This is exactly why real curves use a base point of huge prime order (secp256k1: n ≈ 2256).


Statistical exploration


    

  • Coordinates. The points kG and (n−k)G are opposite: they share x and have y mirrored (y → −y mod 17). With n = 9, each x value therefore appears exactly twice and every y once. This is not randomness but a symmetry of the curve. It also explains why the Pearson correlation between k and x is exactly 0 for the default parameters (x(k) = x(9−k) is symmetric around k = 4.5). Zero linear correlation does not mean independence: x is completely determined by k.
    • 

  • Uniformity. When G generates the whole group, kG visits every point exactly once, so the distribution over points is perfectly uniform, but by construction and not statistically. The chi-square test is therefore almost "too good". With a G of small order the test rejects uniformity, because only a subgroup is visited. Bit frequencies depend strongly on p: with p = 17 the values are 5-bit numbers below 17, so the top bit is mostly 0.
    • 

  • Avalanche. Flipping one bit of k changes about 49% of the (x, y) bits for p = 17 and about 48% for p = 10007 (use the "Compare" button; Keccak-256 gives about 50%). That looks hash-like, but it is largely a small-space effect: two unrelated small numbers differ in about half of their bits anyway.
    • 

  • Structure that a hash does not have. (a+b)G = aG + bG holds in every trial, whereas H(a⊕b) = H(a)⊕H(b) essentially never holds for Keccak-256. Scalar multiplication is a group homomorphism, so Q reveals algebraic relations (e.g. (k+1)G = Q + G) that a hash must not reveal.
    • 



Which properties matter for a one-way function and which for a hash


One-way function (scalar multiplication). What matters is: easy forward direction (double-and-add, O(log k) additions), hard inverse (the Elliptic Curve Discrete Logarithm Problem), and a very large prime group order. The best generic attacks, like Pollard's rho, need about √n steps, i.e. ≈ 2128 for secp256k1. The scaling experiment shows brute force growing linearly with n; extrapolating to n ≈ 2256 gives about 1060 years at 109 steps per second, and Pollard's rho still about 1022 years. (Quantum computers running Shor's algorithm would break the ECDLP; that is outside this exercise.) Avalanche, uniformity of outputs and pseudo-randomness are not required for this purpose; indeed the structure of the group is what makes signatures and key derivation (public keys from private keys) possible.


Cryptographic hash function (e.g. Keccak-256). What matters is preimage resistance, second-preimage resistance and collision resistance, a fixed-size output for arbitrary-length input, a strong avalanche effect, outputs that look uniformly random, and no exploitable algebraic structure. Here the "statistical" tests (avalanche, bit balance, uniformity, absence of correlation) are meaningful as sanity checks, although passing them is necessary and not sufficient for security.


Conclusion. Elliptic-curve scalar multiplication is a one-way function based on a hard mathematical problem, not a hash function: it has no fixed-size compression of arbitrary data and it is deliberately algebraic. The statistical properties we measured (avalanche, uniformity, correlation) describe hashes much better than they describe kG, and in the toy case they can even be misleading.
